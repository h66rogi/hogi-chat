# SOOP 채팅 프로토콜

브라우저 플레이어가 쓰는 채팅 WebSocket을 그대로 쓴다. 라이브러리나 공식 문서는 없고,
관찰로 알아낸 내용이다. **읽기는 익명으로 가능하고, 쓰기는 로그인 티켓이 필요하다.**

## 1. 방송 정보 얻기

```
POST https://live.sooplive.co.kr/afreeca/player_live_api.php?bjid=<BJ_ID>
bid=<BJ_ID>&bno=0&type=live&player_type=html5
```

응답 `CHANNEL`에서:

| 필드 | 쓰임 |
| --- | --- |
| `RESULT` | 1이면 방송 중, 0이면 오프라인 |
| `CHATNO` | 채팅방 번호 (JOIN에 필요) |
| `CHDOMAIN`, `CHPT` | WebSocket 호스트·포트. 접속은 `CHPT + 1` |
| `FTK` | 익명 입장 티켓. 로그인 상태에서는 빈 값으로 보낸다 |
| `TITLE` | 방송 제목 |
| `USERID`, `SUB_PAY_CNT`, `TIER_TYPE` | 쿠키를 실어 보낼 때만 온다(내 계정 상태) |

쿠키 없이 요청하면 `FTK`가 비로그인용이라 채팅방에 "구독 안 한 사람"으로 들어간다.
로그인 쿠키(`AuthTicket`)를 실으면 같은 응답에 내 계정 정보가 오고 `FTK`도 내 계정용으로 바뀐다.

## 2. 패킷 형식

```
ESC(0x1B) TAB(0x09) CMD(4자리 ASCII) BODYLEN(6자리 ASCII) RET(2자리 ASCII) BODY
```

- 헤더 14바이트. 필드는 `0x0C`(폼피드, `\f`)로 구분한다.
- 본문 앞뒤의 `\f`는 제거하고 나눈다.
- 수신은 헤더가 어긋날 수 있으므로 `ESC TAB`을 찾아 스캔하고, 길이를 읽어 다음 패킷으로 넘어간다.

```
packet = b"\x1b\t" + f"{cmd:04d}{len(body):06d}00".encode() + body
```

## 3. 읽기 (익명)

1. `CMD 1`, body `\f\f\f16\f` — 익명 로그인(flag 16). 응답 `CMD 1`.
2. 응답을 받으면 `CMD 2`, body `\f{CHATNO}\f{FTK}\f0\f\f\f` — JOIN.
3. 이후 `CMD 5`(SVC CHATMESG)가 흐른다. 필드: `[0]=본문`, `[1]=userId(nick)`, `[5]=닉네임`,
   `[6]`·`[7]`은 표시 플래그·구독 개월(로그인 입장에서만 채워짐).
4. `CMD 7`은 방송 종료 계열 신호로 처리했다.
5. 60초마다 `CMD 0`(body `\f`)을 보내 연결을 유지한다.

## 4. 쓰기 (로그인)

1. 쿠키에서 `AuthTicket`을 꺼낸다.
   macOS Chromium 계열 프로필이면 `read_cookies.py`로 복호화한다: `v10` AES-CBC, 키는 키체인
   `Aside Safe Storage`(또는 브라우저 Safe Storage), 복호화 결과 앞 32바이트 제거.
2. `CMD 1`, body `\f{AuthTicket}\f\f16\f` — 로그인.
   응답 첫 필드가 `id(N)` 형태이고 `N`이 2 이상이면 로그인 성공(게스트는 16).
3. `CMD 2` — JOIN. 로그인 상태에서는 `FTK`를 **빈 값**으로 보낸다. 값을 넣으면 무응답.
   웹 플레이어와 같은 본문을 쓰려면 `log\x11...=...\x12pwd\x11\x12auth_info\x11NULL\x12` 블록을 붙인다.
4. JOIN 응답 본문의 인덱스 7에 `ENTER_INFO` 값이 있으면 `CMD 12`, body `\f{값}\f0\f`를 보낸다.
   이걸 보내야 내 계정 상태(구독 등)가 채팅방에 적용된다.
5. 전송: `CMD 5`, body `\f{메시지}\f0\f`.
   - **본문 맨 앞에 UUID를 넣으면 그 UUID가 메시지로 표시된다.** 처음 시도에서 실제로 방송에 UUID가 노출됐다.
   - 정상 전송도 응답 `CMD 5`의 `ret`이 0으로 온다(5도 성공). 성공 판정은 `ret in (0, 5)` **그리고**
     돌아온 본문이 보낸 문장과 같은지로 한다. `ret`만 보고 판정하면 실패를 성공으로 읽는다.

## 5. 함정 정리

- 로그인 JOIN에 `FTK`를 넣으면 응답이 없다. 익명일 때만 쓴다.
- 패킷 본문은 항상 `\f`로 시작·끝나야 한다. JSON으로 보내면 조용히 무시된다.
- 전송 성공 판정은 에코 비교까지 해야 한다.
- 같은 서버에서 SOOP 수신 세션을 하나 더 열면 `IncompleteReadError`로 거절된다(2026-10-24 실측).
  전사 비교 실험은 기존 세션이 받는 조각을 복사해서 했다.
- 쿠키 없이 방송 정보를 받으면 FTK가 달라져 구독 표시가 사라진다. 읽기·쓰기 모두 쿠키를 실어야 같은 계정이 된다.

| 2026-10-24 | 쿠키 실은 요청에서 `SUB_PAY_CNT`·`TIER_TYPE` 확인, ENTER_INFO 필요성 확인 |
| 2026-10-24 | 전송 응답이 `ret=0`/`ret=5` 두 형태로 오는 것 확인 |

이 프로토콜은 공개 문서가 아니고 언제든 바뀔 수 있다. 운영에 쓰려면 매번 현재 플레이어로 재확인해야 한다.
