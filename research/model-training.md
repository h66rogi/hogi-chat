# 모델 학습 검토

"프롬프트 + 예시"에서 시작해 어디까지 갈 수 있는지, 대안은 무엇인지 정리한 기록이다.
결론부터: **지금 필요한 것은 더 큰 모델이 아니라 더 깨끗한 판정 데이터**였다.

## 단계별 선택지

| 단계 | 방식 | 장점 | 한계 |
| --- | --- | --- | --- |
| A | 프롬프트 + few-shot | 즉시 적용, 비용 0, 롤백 쉬움 | 표현이 수렴하지 않고 매번 흔들림 |
| B | 유사 상황 RAG | 파인튜닝 없이 일관성 향상, 데이터가 이미 있음 | 검색 대상이 좁으면 과거 발화 복사로 흐름 |
| C | 승인/거부 판정 분류기 | 생성기를 고치지 않고 필터만 개선, 200~500건이면 학습 | 판정 데이터 품질에 전부 의존 |
| D | LoRA/QLoRA 파인튜닝 | 말투·형식이 안정 | 라벨 노이즈에 취약, 실시간 지연 위해 GPU 필요 |

권장 순서: A(당시) → B → C(판정 200건부터) → D(승인 1,000건 이후).
D를 서두르면 안 되는 이유는 아래 "복사 보상" 문제 때문이다.

## RAG만으로는 왜 부족한가

전체 아카이브를 검색 대상으로 키우면 오히려 나빠진다.

- 유사도가 얕다. 채팅 몇 줄의 임베딩 유사도는 "웃는 중" 정도만 잡는다. 다른 방송에서 비슷해 보이는 순간이
  실제로 같은 상황인 경우는 드물다.
- 흔한 반응만 돌아온다. 수백만 채널에서 검색하면 `ㅋㅋㅋ`, `ㄹㅇ` 같은 반응이 상위에 온다. 내 말투는 사라진다.
- 규칙 위반이 섞인다. 다른 방송 반응에는 타 스트리머 이름·시청자 닉·고유명사가 많다.

그래서 RAG는 **내 발화 2~3천 건 규모의 좁은 검색**으로만 썼다(2-gram 겹침 기준, 최근 흐름과 비교).

## 학습 쌍 정의

- 입력: 직전 60~90초의 채팅 흐름(평균 14.6줄, 163자)
- 정답: 그다음에 실제로 나온 채팅 1줄(평균 10자)
- 토큰: 약 **150** (Qwen3.5 토크나이저 1만 쌍 실측)

아카이브에는 채팅만 있으므로 이 쌍으로 얻는 것은 "채팅 흐름 감각"이다.
BJ 발화 이해·상황 파악은 기반 모델 실력에 의존한다(추정).

판단 모델(칠 타이밍·반응 종류 분류)은 1억~3억 파라미터로 충분하다.
1,000만 쌍 학습 $3~11, 5,000만 쌍 $17~54 추정. 정답은 다음 채팅에서 규칙으로 뽑을 수 있어 추가 비용이 없다.

## 크기 선택 (9B vs 27B)

이 용도로 9B/27B를 학습해 비교한 사례는 없어서 단정할 수 없다. 판단 근거만 정리하면:

- 크기 영향이 작은 부분: 짧은 말투·형식 모방, 방송 규칙 준수(필터·후처리로 보완 가능)
- 크기 영향이 큰 부분: BJ 말 이해, 맥락 파악, 웃음 포인트, 한국어 자체
- 중간 선택지: MoE(35B-A3B, 26B-A4B). 메모리는 27B급, 계산은 3~4B급이라 빠르고 학습 단가는 27B와 같다

평가 설계(권장):

1. 학습에 쓰지 않은 실제 방송 채팅으로 다음 채팅 예측 정확도 비교
2. 방송 중 상태 카드에 9B·27B·기존 API 모델 후보를 **출처를 숨기고** 섞어 띄워 승인률 비교(2~3회 방송이면 표본)

## 데이터 반출 제약

대규모 아카이브는 외부에서 제공받은 데이터이고 이 프로젝트에 재배포 권한이 없다.
외부 학습 서비스에 올리면 원문이 그 업체로 나간다. 사용자 ID·닉네임 컬럼을 빼도 본문은 남는다.
**이 프로젝트에서는 아카이브 원문을 외부로 반출하지 않았다.** 학습을 재개한다면 이 판단을 먼저 다시 해야 한다.
