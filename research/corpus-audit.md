# 코퍼스 감사

학습을 검토하려면 먼저 데이터가 어떤 모양인지 재야 했다. 두 코퍼스를 감사했다:
(1) 대규모 통합 채팅 아카이브, (2) 내 채널·내 계정에서 모은 소규모 코퍼스.

## 1. 대규모 아카이브 (2026-04-07 ~ 07-15)

국내 인터넷방송 3사 통합 채팅 아카이브(운영사 제공, 접근 권한·보관 위치는 비공개).
Parquet 시간별 파티션을 DuckDB로 메타데이터만 먼저 훑고, 표본을 뽑아 본문 특성을 쟀다.

| 항목 | 값 |
| --- | --- |
| 시간별 파일 | 2,349개 |
| 총 행 | **17.4억** |
| 플랫폼 분포 | A 9.2억 / B 7.8억 / C 1,700만 |
| 후원 메시지 | 약 1,800만 |
| 채널 수(근사) | A 5.4만 / B 2.9만 |
| 직전 60초에 같은 채널 채팅 5줄 이상 | 75% |
| 학습 쌍 환산 (60초/5줄 기준) | **약 13억** |
| 학습 쌍 환산 (20줄 기준) | 약 6.4억 |
| 평균 채팅 길이 | A 11.5자 / B 9.2자 |
| 15자 이하 비율 | 79~86% |
| 링크·@멘션 | 0.1% 미만 |

쌍 환산은 무작위 49시간 표본 기준 추정이다. 표본을 처음에는 같은 시간대에서 뽑아 편향이 있어서
무작위 시간대로 다시 뽑아 값을 바꿨다.

**측정 중 발견한 함정**

- 일부 행에 깨진 문자열이 있어 DuckDB `read_parquet`가 `Invalid string encoding`으로 실패한다.
  pyarrow로 읽으면 넘어간다. 전체 스캔 스크립트는 이 예외 때문에 두 단계가 실패했다가 재실행으로 해결됐다.
- 쌍 하나의 토큰 수는 실제 토크나이저로 쟀다: 직전 채팅 평균 14.6줄(163자) + 다음 채팅 10자 = **약 150토큰**.
  이 값이 학습 비용 계산의 기준이 됐다(초기 추정 250토큰은 과대했다).
- 방송 시간은 "5분 버킷에 채팅 3줄 이상"을 방송 중으로 보는 프록시로 셌다.
  10일 중 9일 방송, 합계 43.3시간 → **월 약 130시간**.

## 3. 핵심 발견: 판정 데이터가 학습 신호가 아니었다

- 판정률 12/196 = 6%. 대부분 판정되지 않았다.
- 승인 6건 **전부** 내 과거 발화와 글자 단위로 일치했다.
- 생성 프롬프트에 고정 예시 10개가 박혀 있었으므로, 생성기는 "예시를 그대로 쓰면 승인"을 학습할 수 있었다.

즉 승인은 취향 신호가 아니라 **복사 보상**이었다. 이 상태로 분류기나 파인튜닝을 하면
"내가 이미 한 말을 그대로 반복하는 모델"을 만든다.

조치(코드에 반영):

1. 프롬프트에서 고정 예시를 제거하고 금지 목록으로만 사용
2. 승인/거부 예시를 넣을 때 시드 코퍼스와 글자 일치하는 것은 제외(홀드아웃)
3. 승인 데이터 1,000건 전에는 분류기·파인튜닝에 쓰지 않음
4. 같은 문장 10분 내 재전송 금지, 최근 후보와 유사도 비교

## 5. 결론

- 대규모 아카이브는 **쌍 생성은 쉽고 라벨이 없다.** 다음 채팅을 정답으로 쓰는 자기지도 학습만 가능하다.
  취향(내가 승인할 문장)은 여기서 나오지 않는다.
- 내 코퍼스는 규모가 작고(수백), 판정이 오염돼 있었다. **데이터를 늘리기 전에 수집 절차를 고쳐야 한다.**
- 방송당 수집량은 3줄/분 수준이라 한 방송에 수백 줄이다. 승인 1,000건을 모으려면 수십 회 방송이 필요하다.
